# Monthly Editorial Workflow

## Phase 1: Editorial Direction

Owners:
- `editorial_strategy`
- `editor_in_chief`

Tasks:
- review Poblysh pillars
- define monthly theme
- define central tension
- define intended reader effect
- define mood and no-go zones

Output artifact:
- `monthly-theme-brief.md`

## Phase 2: Issue Architecture

Owner:
- `issue_planner`

Tasks:
- convert one monthly theme into four essay territories
- assign opener, widening, consequence, and closing roles
- ensure no redundancy
- map business functions touched by each essay

Output artifact:
- `issue-map.md`

## Phase 3: Essay Framing

Owner:
- `essay_architect`

Tasks for each essay:
- thesis
- primary tension
- misconception corrected
- business functions touched
- title directions
- statement-line candidates
- pacing bias

Output artifact:
- `essay-brief.md`

## Phase 4: Reader Hook Test

Owner:
- `reader_perspective_critic`

Tasks:
- test title strength
- test hook clarity
- test curiosity promise
- test whether the concept can sustain mobile reading

Output artifact:
- `critique-report.md`

## Phase 5: Editorial Approval

Owner:
- `editor_in_chief`

Approval scope:
- monthly theme
- issue map
- per-essay brief
- sequencing logic
- strongest tension of each piece
